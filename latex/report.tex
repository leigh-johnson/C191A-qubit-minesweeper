\section{Introduction}

Building a fault-tolerant quantum computer requires correcting a variety of physical errors that arise in real hardware. In this work, we focus on how erasure-aware decoding influences the noise threshold of the rotated surface code, and how different decoders (MWPM vs. MWPF) respond to Pauli versus erasure-dominated noise. This section summarizes the key concepts that motivate our experiments and connects them to recent work on erasure qubits and erasure conversion in superconducting and neutral-atom platforms \cite{fowler_surface_2012}\cite{kubica_erasure_2023}\cite{gu_fault-tolerant_2025}\cite{sahay_high-threshold_2023}\cite{chadwick_erasure_2025}.

Motivation: Fault-tolerate quantum computation at scale remains a formidable challenge, but we're excited about these recent major advancements:

Decoding with erasure information dramatically increases the surface code error threshold from 0.937\% to 4.15\%, with an estimated 98\% of errors convertible into erasures. \cite{wu_erasure_2022}

Machine-learned error decoding for quantum processors (surface code) by Bausch et al uses a transformer-based neutral network to decode error data with realistic noise models, including qubit cross-talk and state leakage.

"Requires a system capable of dissipatively removing physical errors while simultaneously performing arbitrary coherent manipulation of the encoded logical qubits."  \cite{bluvstein_architectural_2025}

\section{Background \& Related Work}

\subsection{Noise Models}
\paragraphsc{Pauli Noise.}
Quantum processors experience several classes of errors. A common simplification is to model all physical noise as independent Pauli errors, sampled uniformly from $\set{X,Y,Z}$. For the surface code this is often instantiated as a depolarizing channel \cite{fowler_surface_2012,pesah_interactive_2023}:
\begin{align}E_{\text{pauli}}(\rho) & = (1-p)\rho + \dfrac{p}{3}(X\rho X + Y\rho Y + Z\rho Z) & \quad \text{[Depolarizing error channel]}
\end{align}

Pauli noise has become the standard baseline for evaluating code performance and thresholds in both early and recent large-scale experiments \cite{fowler_surface_2012}\cite{acharya_quantum_2025}.


\paragraphsc{Leakage.}
However, this model does not capture important features of real devices. A particularly harmful type of hardware noise is leakage, where population escapes the computational subspace into higher energy levels (e.g.,$\ket{2}$ in a weakly anharmonic oscillator) and can persist across many QEC cycles, producing spatially and temporally correlated errors \cite{suchara_leakage_2014}\cite{wilen_correlated_2021}\cite{miao_overcoming_nodate}\cite{yang_coupler-assisted_2024}. To mitigate this, many proposals and recent experiments introduce leakage-reduction units (LRUs) or related mechanisms that periodically detect and reset leaked qubits \cite{suchara_leakage_2014}. See \nameref{appendix:leakage} for a more detailed description.

\paragraphsc{Erasure.} An erasure occurs when a qubit is longer detectable by the measurement device, so the quantum state information encoded by the qubit is effectively ``lost'' or ``erased''. Mathematically, we extend the qubit Hilbert space with some $\ket{e}$ that is orthogonal to the qubit state $\{\ket{0}, \ket{1}\}$. The erasure channel can be defined as:

\begin{align}E_{\text{erase}}(\rho_j) & = (1-p_{\text{erase}})\rho_j + p_{\text{erase}}\ket{e}\bra{e} & \quad \text{[Erasure error channel \cite{suchara_leakage_2014}]}
\end{align}

Unlike unknown Pauli errors, the location of an erasure is known to the decoder. This structural information dramatically changes the performance of error-correcting codes and has been formalized in recent work on erasure qubits and erasure-based architectures \cite{kubica_erasure_2022} \cite{gu_fault-tolerant_2025} \cite{gu_optimizing_2024}.

For a distance $d$ error-correcting code, up to $\dfrac{d-1}{2}$ arbitrary Pauli errors but up to $d-1$ erasures, because the decoder knows which qubits are affected. \cite{kubica_erasure_2023} \cite{gu_fault-tolerant_2025}.

This asymmetry leads to substantially higher thresholds and more favorable scaling in the erasure-dominated regime. Circuit-level simulations and code-capacity analyses of the surface code and related architectures consistently find erasure thresholds far above those for depolarizing noise—on the order of tens of percent for tailored codes—compared to ~1\% at the circuit level. \cite{wu_erasure_2022} \cite{sahay_high-threshold_2023} \cite{gu_optimizing_2024}.

The erasure paradigm is not purely theoretical. In neutral-atom hardware, metastable Yb qubits, Rydberg entangling gates, and fast, state-selective imaging enable mid-circuit conversion of dominant errors into detectable erasures \cite{wu_erasure_2022}\cite{ma_high-fidelity_2023}\cite{scholl_erasure_2023} \cite{chow_circuit-based_2024}
\cite{norcia_midcircuit_2023}\cite{reichardt_fault-tolerant_2025}. Similar ideas are being pursued in superconducting circuits via dual-rail encodings and tailored measurement schemes \cite{kubica_erasure_2023} \cite{gu_fault-tolerant_2025} \cite{gu_optimizing_2024}, and in hybrid architectures that strategically deploy erasure qubits to trade physical cost for logical performance \cite{chadwick_erasure_2025} \cite{baranes_leveraging_2025}. These works collectively motivate studying how erasure-aware decoders perform on the surface code under idealized Pauli vs. erasure noise models, as we do here.

At the same time, erasure detection is imperfect and requires additional physical operations. Extra erasure checks may introduce correlated errors or additional decoherence, and realistic erasure-conversion schemes rarely achieve 100\% conversion efficiency \cite{ma_high-fidelity_2023}\cite{wu_erasure_2022}\cite{gu_optimizing_2024}. This motivates separating "pure Pauli" and "pure erasure" regimes in simulations as a first step, which we adopt in this project.

\subsection{Erasure Qubits}

A qubit engineered so the dominant source of errors is from erasures. A bias towards erasure-type errors occurs natively in some types of qubits (e.g. photons) or can be engineered by converting leakage errors to erasures (e.g. with LDUs in superconducting qubits). For more information on how erasure conversion works for neutral atoms, refer to the following papers: \cite{wu_erasure_2022} \cite{baranes_leveraging_2025} For superconducting qubits, refer to the following papers: \cite{gu_optimizing_2024} \cite{gu_fault-tolerant_2025}.

\subsection{Surface Code}\label{subsec:surface-code}

The \emph{surface code} is a leading candidate for fault-tolerant quantum computation due to its local stabilizers, high threshold, and compatibility with two-dimensional hardware architectures~\cite{fowler_surface_2012}\cite{pesah_interactive_2023}. In its rotated layout, a single logical qubit is encoded across a $d \times d$ lattice of physical qubits, with repeated stabilizer measurements producing a space--time syndrome history. The code distance $d$ sets the minimum number of physical errors required to implement a logical error.

If the physical error rate $p$ is below a threshold $p_{\mathrm{thr}}$, the logical error rate $P_L$ decreases approximately exponentially with $d$:
\begin{align}
    P_L \propto \left( \frac{p}{p_{\mathrm{thr}}} \right)^{(d+1)/2} \quad \text{{Logical error rate}}
\end{align}
a scaling extensively validated in both simulations and experiments~\cite{fowler_surface_2012,fowler_optimal_2013,acharya_quantum_2025,bluvstein_logical_2024}. This exponential suppression underpins scalable, fault-tolerant architectures. Recent work has begun to explore how accumulated erasures, atom loss, and code deformations affect surface-code thresholds in neutral-atom settings, motivating specialized schemes for handling ongoing erasure processes~\cite{kobayashi_erasure-tolerance_2025,reichardt_fault-tolerant_2025,li_fast_2025}.

Because erasure errors are easier to correct and reveal additional information to the decoder (example: \autoref{fig:surface-code-erasure-comparison}), the erasure-aware threshold can be substantially higher than the threshold under Pauli noise, especially when decoders are explicitly optimized for erasure structure~\cite{sahay_high-threshold_2023,gu_fault-tolerant_2025,gu_optimizing_2024}. Quantifying this gap for practical decoders is one of the main goals of our study.



\paragraphsc{Circuit-level Noise Thresholds.}
If physical qubit error is below a critical noise threshold, the logical error rate should be supressed exponentially as the number of physical qubits per logical qubit is increased. In the surface code, the approximate relation between $d$ code distance corresponding to $2d^2 - 1$ physical qubits per logical qubit, the physical error rate $p$, logical error rate $E_d$, and error rate threshold $p_{thr}$  \cite{acharya_quantum_2025}.

\subsection{Decoding: MWPM vs.\ MWPF}
\label{subsec:decoding}

Decoding the surface code requires inferring which error configurations could have produced a given syndrome history. The two decoders we evaluate---MWPM and MWPF---differ fundamentally in how they represent and exploit error information.

\subsubsection{Minimum-Weight Perfect Matching (MWPM)}

\textbf{MWPM decoders} (e.g., PyMatching) cast the decoding problem as a \emph{graph matching} task: syndrome defects are nodes, edges represent possible error events, and a minimum-weight perfect matching yields the most likely Pauli error configuration consistent with the observed syndrome~\cite{oscarhiggott_oscarhiggottpymatching_2025}\cite{higgott_sparse_2025,gidney_answer_2023-1}. This approach has become the de facto standard for decoding the surface code under uncorrelated Pauli noise~\cite{fowler_surface_2012}\cite{fowler_optimal_2013}. Our baseline simulations follow this tradition, using Stim and MWPM-based decoders to estimate thresholds under depolarizing noise \cite{gidney_stim_2021}.

However, the standard MWPM formulation assumes:
\begin{itemize}
    \item errors are well-approximated as \textbf{independent Pauli faults}, and
    \item the decoder has no side information about \emph{where} errors occurred.
\end{itemize}

In particular, MWPM does not naturally exploit the additional structure provided by erasure events, where locations of faults are known but their Pauli type is not. Extensions exist that partially incorporate erasure information within a matching framework, particularly for erasure qubits~\cite{kubica_erasure_2023,gu_fault-tolerant_2025}, but these remain limited compared to full hypergraph methods.

\subsubsection{Minimum-Weight Parity Factor (MWPF)}

The \textbf{MWPF decoder} generalizes this picture by representing the error model as a \emph{hypergraph}, where a single error mechanism can flip the parity of an arbitrary subset of detectors, not just pairs~\cite{wu_yuewuomwpf_2025,wu_minimum-weight_2025}. This allows MWPF to natively capture:
\begin{itemize}
    \item multi-qubit correlated error events,
    \item erasure-tagged qubits and their constraints,
    \item realistic detector error and measurement models across general quantum LDPC codes.
\end{itemize}

In the MWPF framework, decoding becomes a \emph{minimum-weight parity factor} problem: find a set of hyperedges whose parities match the observed syndrome while minimizing the total weight derived from the noise model~\cite{wu_minimum-weight_2025}. Hypergraph matching is NP-hard in general, but the HyperBlossom implementation used in this work employs primal--dual relaxations, clustering, and sparse data structures to achieve near-linear average runtime scaling on surface codes and other LDPC codes at relevant code distances~\cite{wu_minimum-weight_2025}.

By construction, MWPF can incorporate erasure locations directly into the decoding graph, rather than approximating them as effective Pauli faults. This is especially powerful in architectures that deliberately convert dominant noise channels to erasures~\cite{wu_erasure_2022,kubica_erasure_2023,gu_fault-tolerant_2025,chadwick_erasure_2025}. Our experiments leverage this capability by comparing MWPF and MWPM in regimes where erasures are either absent (pure Pauli noise) or dominant (pure erasure noise).

\subsection{Motivation for Our Experiments}
\label{subsec:motivation}

The literature sketched above suggests a coherent picture:

\begin{enumerate}
    \item Real hardware produces Pauli errors, leakage, and loss;
          \textbf{leakage-reduction and mid-circuit detection convert a large fraction of these into erasures}
          in both neutral-atom and superconducting platforms%
          \cite{wu_erasure_2022,ma_high-fidelity_2023,scholl_erasure_2023,
              chow_circuit-based_2024,kubica_erasure_2023,gu_fault-tolerant_2025}.

    \item \textbf{Erasures are significantly easier to correct} than unknown Pauli errors and can
          dramatically improve thresholds and overhead when properly exploited%
          \cite{sahay_high-threshold_2023,gu_optimizing_2024,baranes_leveraging_2025,
              chadwick_erasure_2025}.

    \item The \textbf{surface code threshold} depends strongly on the decoder’s ability
          to use erasure information, as seen in simulations and early fault-tolerant experiments%
          \cite{fowler_surface_2012,acharya_quantum_2025,bluvstein_logical_2024,
              reichardt_fault-tolerant_2025,kobayashi_erasure-tolerance_2025}.

    \item \textbf{MWPF} explicitly incorporates erasure locations and correlated error mechanisms
          through a hypergraph formulation, while \textbf{MWPM} is tuned for uncorrelated Pauli noise%
          \cite{oscarhiggott_oscarhiggottpymatching_2025,higgott_sparse_2025,
              wu_minimum-weight_2025}.
\end{enumerate}

These observations motivate our study: by comparing MWPM and MWPF on the rotated surface code under both Pauli-only and erasure-dominant noise, we aim to quantify how erasure-aware decoding reshapes the threshold landscape and to clarify systematic deviations between ``idealized'' literature thresholds and practical simulation results obtained with Stim- and MWPF-based workflows. In this work, we simulate rotated-surface-code memory circuits under depolarizing and erasure noise using Stim. We compare MWPM and MWPF decoders across distances $d \in \set{3, 5, 7, 9, 11}$, with Monte Carlo sampling to estimate logical error rates and extract threshold behavior. This allows us to quantify how erasure-aware decoding reshapes threshold scaling compared to conventional Pauli-only error decoding.

\section{Results}\label{sec:results}
\paragraphsc{Surface Code Threshold.}\label{sec:results-overview} We studied the performance of a rotated surface code under various noise and error syndrome decoding regimes (\autoref{tab:1}), with the goal of observing the impact of erasure conversion on our definition of the fault-tolerant error threshold $p_{thr}$. Using Stim \cite{gidney_stim_2021} to simulate the surface code stabilizer circuit, we perform Monte Carlo simulations of a $d \times d$ array of qubits representing an X-rotated surface stabilizer with code distance $d \in \set{3, 5, 7, 9, 11}$, physical error rate $p \in [0.001, 0.06]$, and erasure error conversion rate $R_e \in [0, 1]$.

Noise channels are applied to individual qubits \textit{before} each round (state preparation) and \textit{after} each Clifford gate operation with $p$ probability. We prepare the state $\ket{+}$ and estimate the logical error rate $P_L$ after $d$ rounds of measurements in the X-basis, assuming perfect syndrome measurements ($p_{measure} = 0.0$). As a baseline, we model standard Pauli noise by sampling errors uniformly at random from the set $\set{I, X, Y, Z}$, corresponding to the \verb|DEPOLARIZE1| (single-qubit) and \verb|DEPOLARIZE2| (two-qubit) simulated error channels.

We explore the impact of erasure error conversion by implementing the error model described in \cite{wu_erasure_2022} with some notable differences: each physical qubit experiences either a Pauli error occurring with probability $p_{pauli} = p(1-R_e)$ or an erasure with probability $p_e = pR_e$. Notably, we simulate $R_e=0$ and $R_e=1$, representing 0\% and 100\% erasure conversion respectively. We apply this noise model to \textit{all} Clifford gates (both one and two qubit gates). After an erasure error is detected, the affected qubit is reset to a maximally mixed state $I/2$. The resulting syndrome measurements are decoded to determine whether the shot can be corrected or results in a logical error.

We define $p_{thr}$ as the physical error rate $p$ where the logical error rate $P_L$ decreases as a function of $d$. To estimate $p_{thr}$, we identify crossing points in \autoref{fig:best-threshold-comparison}, where the logical error rate decreases as code distance $d$ increases, with the d=3,5 and d=9,11 crossings representing the lower and upper bound of $p_{thr}$ respectively. The highest $p_{thr}$ was 3.02\% when $R_e=1.0$ using the erasure-aware hypergraph MWPF decoder, compared to a 0.75\% threshold using the MWPF decoder in a pure Pauli noise regime. The procedure for circuit simulation, event sampling, and decoding is documented in \nameref{sec:experiment2} and \nameref{sec:experiment3}.

\subsection{Experiment 1: Min-weight Perfect Matching Baseline.} \label{sec:experiment1}
\begin{itemize}
    \item Data: \href{https://github.com/leigh-johnson/C191A-qubit-minesweeper/tree/main/datasets/circuit%3Dsurface_code%3Arotated_memory_x/decoder%3Dpymatching}{Github Link}
    \item Additional results: \autoref{fig:pymathing-pthresh}.
\end{itemize}

\paragraphsc{Procedure.} We consider $R_e=0.0$ with a purely Pauli noise regime. We apply a minimum-weight perfect matching (PyMatching) decoder, with the syndrome decoding process split between two phases:
\begin{itemize}
    \item \textbf{Offline phase} (once per unique combination of swept parameters)

          For each choice of code distance $d$, physical error rate $p$, and erasure conversion rate $p_e$,
          we compile the Stim circuit into a \emph{detector error model} (DEM) \cite{gidney_stim_2021}.
          The DEM defines a collection of binary detectors $\{D_i\}_{i=1}^m$ and a collection of
          error mechanisms $\{E_j\}_{j=1}^n$. Each error mechanism $E_j$ is annotated with the subset of
          detectors it flips. This defines a binary parity-check matrix: \footnote{We understand the binary parity-check matrix as a Tanner graph, a type of bipartite graph used in classical low-density parity-check error-correcting codes. \cite{noauthor_tanner_2025}}
          \begin{align*}
              H \in \{0,1\}^{m\times n}, \qquad
              H_{ij} =
              \begin{cases}
                  1 & \text{if error mechanism } E_j \text{ flips detector } D_i, \\[4pt]
                  0 & \text{otherwise}.
              \end{cases}
          \end{align*}

          Each column of $H$ has Hamming weight 1 or~2, so we can represent the parity check matrix as a graph where column $j$ corresponds to either an edge between two detectors or a half-edge connecting a detector to a boundary node.
          Each column $j$ is assigned an edge weight $w_j$ derived from the probability $p_j$ of the error
          mechanism $E_j$: \cite{higgott_sparse_2025}
          \begin{align*}
              w_j \approx \log\!\left(\frac{1 - p_j}{p_j}\right).
          \end{align*}

          These data $(H, \{w_j\})$ are used to construct a \texttt{pymatching.Matching} object \cite{oscarhiggott_oscarhiggottpymatching_2025}.

    \item \textbf{Online phase:} syndrome measurement and minimum-weight decodings (per shot)

          During Monte Carlo simulation, each noisy circuit shot produces a binary syndrome vector:
          \begin{align*}
              \mathbf{s} \in \{0,1\}^m,
          \end{align*}
          where $s_i$ is the value of detector $D_i$ for that shot.
          If we let $\mathbf{x} \in \{0,1\}^n$ be some unknown binary error vector, with $x_j = 1$ indicating
          that error mechanism $E_j$ occurred. The detectors then must be constrainted to the solutions for:
          \begin{align*}
              H \mathbf{x} = \mathbf{s} \pmod{2}.
          \end{align*}

          For binary syndrome vector $\mathbf{s}$, \texttt{PyMatching} solves the minimum-weight decoding problem on the graph $H$ with the Sparse Blossom algorithm \cite{higgott_sparse_2025}, an implementation of MWPM designed for fast computations. The authors of Sparse Blossom explot the fact that the decoder only needs to predict which logical observables were flipped, rather than the physical errors.  \footnote{ For a textbook-quality explanation of decoding error syndromes in the surface code, see Craig Gidney's answer to StackExchange post: "Can you give an intuitive idea behind how the Minimum Weight Perfect Matching (MWPM) decoder works?"\cite{gidney_answer_2023-1} }. The result $\hat{\mathbf{x}}$ is mapped to a corresponding Pauli correction on the data qubits. We assume
          \begin{align*}
              \hat{\mathbf{x}}
              = \arg\min_{\mathbf{x} \in \{0,1\}^n}
              \left\{
              \sum_{j=1}^n w_j x_j
              \;:\;
              H \mathbf{x} = \mathbf{s} \pmod{2}
              \right\},
          \end{align*}
          The result $\hat{\mathbf{x}}$ is mapped to a corresponding Pauli correction on the data qubits.
          Comparing the corrected logical measurement to the ideal value determines whether the shot
          contributes to the logical error rate $P_L$.
\end{itemize}

\subsection{Experiment 2: Min-weight Parity Factor Baseline } \label{sec:experiment2}
\begin{itemize}
    \item Data:  \href{https://github.com/leigh-johnson/C191A-qubit-minesweeper/tree/main/datasets/circuit%3Dsurface_code%3Arotated_memory_x/decoder%3Dmwpf/erasure%3D0.0/solver%3DSolverSerialJointSingleHair}{Github Link} 
    \item Additional results: \autoref{fig:mwpf-pthresh}.
\end{itemize}


\paragraphsc{Overview.} In this experiment we study the performance of the minimum-weight parity factor (MWPF) decoder in the uniform Pauli noise regime, as ablation against the MWPM baseline. Except for the decoder, this experiment is identical to \autoref{sec:experiment1}.  Notably, we do not use the version of the \verb|mwpf| decoder bundled with Stim in \verb|sinter\.decoders| and instead run our initial experiments with \verb|mwpf[stim]@0.2.12|. Later on, we incorporate an alternative memory layout in a fork of mwpf.

\paragraphsc{Procedure.}
\begin{itemize}
    \item {\textbf{Offline phase:} hypergraph detector error model and incidence matrix.}

          For each choice of code distance $d$, physical error rate $p$, and erasure conversion rate $p_e$,
          we compile the Stim circuit. We pass the circuit reference to the MWPF library via \verb|SinterMWPFDecoder|, which constructs the DEM \cite{wu_yuewuomwpf_2025}\cite{gidney_stim_2021}.
          The DEM again defines a set of binary detectors
          $\{D_i\}_{i=1}^m$ and a set of error mechanisms $\{E_j\}_{j=1}^n$. Unlike the biparite graph constraint used
          by \texttt{PyMatching}, the \texttt{MWPF} decoder allows each error mechanism $E_j$ to flip an \textit{arbitrary subset
              of detectors}, which is interpreted as a hyperedge: $F_j \subseteq \{D_1,\dots,D_m\}$. This defines a hypergraph parity check matrix, which is structured like an incident matrix having columns that can have \textit{more than} 2 non-zero entries. We compare with the incident matrix in Experiment1, where the columns had \textit{at most} 2 non-zero entries.
          \begin{align*}
              H^{(\mathrm{hyp})} \in \{0,1\}^{m\times n}, \qquad
              H^{(\mathrm{hyp})}_{ij} =
              \begin{cases}
                  1 & \text{if detector } D_i \text{ is incident on hyperedge } F_j, \\[4pt]
                  0 & \text{otherwise}.
              \end{cases}
          \end{align*}
          Each column of $H^{(\mathrm{hyp})}$ may have Hamming weight greater than 2, corresponding to
          hyperedges that touch more than two detectors, but in this baseline experiment all noise is still
          pure Pauli noise (no erasures), so many columns remain graphlike.

          Each error mechanism $E_j$ has an associated error probability $p_j$ determined by the circuit-level noise model. Like in Experiment1, assign a log-likelihood weight to each edge and pass \cite{wu_yuewuomwpf_2025}:
          \begin{align*}
              w_j \approx \log\!\left(\frac{1 - p_j}{p_j}\right),
          \end{align*}

    \item {\textbf{Online phase:} syndrome measurement and minimum-weight parity factor decoding.}

          During Monte Carlo simulation, each noisy circuit shot produces a binary syndrome vector
          \begin{align*}
              \mathbf{s} \in \{0,1\}^m,
          \end{align*}
          where $s_i$ is the outcome of detector $D_i$ for that shot. Again we define some unknown binary error vector $\mathbf{x} \in \{0,1\}^n$, with $x_j = 1$ indicating that error mechanism $E_j$ has occurred. The parity constraints imposed by the detectors can then be written as:
          \begin{align*}
              H^{(\mathrm{hyp})}\, \mathbf{x} = \mathbf{s} \pmod{2}.
          \end{align*}
          Given a measured syndrome $\mathbf{s}$, the MWPF decoder searches over subsets of hyperedges
          (parity factors) to find a minimum-weight explanation of the syndrome. This corresponds to solving
          \begin{align*}
              \hat{\mathbf{x}}
              =
              \arg\min_{\mathbf{x} \in \{0,1\}^n}
              \left\{
              \sum_{j=1}^n w_j x_j
              \;:\;
              H^{(\mathrm{hyp})}\, \mathbf{x}
              =
              \mathbf{s}
              \pmod{2}
              \right\},
          \end{align*}

          Although the solution structure may look similar to Experiment1, the solution set $\mathbf{x}$ are now all the parity factors whose incident hyperedges correspond to the observed detector parities. In the pure Pauli-noise baseline ($R_e = 0$), we understand this methodology to approximate the MWPM because in this special case each error mechanism flips at most two detectors.

\subsection{Experiment 3: Erasure-aware Min-weight Parity Factor } \label{sec:experiment3}
\paragraphsc{Overview.} In this experiment we study the performance of the minimum-weight parity factor (MWPF) decoder in the uniform Pauli noise regime, as ablation against the MWPM baseline. Except for the decoder, this experiment is identical to \autoref{sec:experiment1}.

In this experiment, we repeat the procedure of \nameref{sec:experiment1} but switch from a purely Pauli-noise regime to a full erasure-dominant noise model with 100\% conversion efficiency ($R_e = 1.0$). This setting approximates an idealized version of the erasure-conversion protocols described in \citeauthor{wu_erasure_2022}. Although real physical systems do not achieve $R_e = 1.0$, this extreme regime allows us to isolate the impact of erasure information on the hypergraph decoding scheme.

Notably, we do not use the version of the \verb|mwpf| decoder bundled with Stim in \verb|sinter\.decoders| and instead run our initial experiments with \verb|mwpf[stim]@0.2.12| and then from a forked version with a revised memory layout (see \autoref{sec:memleak-sidequest}).

\paragraphsc{ Additional Results.} See Figure 3c in Section 3, which shows a threshold region around $p_{thr} \in [2.75\%, 3.00\%]$, the highest among all experiments. Due to a memory leak in our implementation of MWPF (see \autoref{sec:memleak-sidequest}), we had to aggregate multiple smaller Monte Carlo batches, resulting in wide confidence intervals at $d \ge 7$.
\paragraphsc{Data.} \href{https://github.com/leigh-johnson/C191A-qubit-minesweeper/tree/main/datasets/circuit%3Dsurface_code%3Arotated_memory_x/decoder%3Dmwpf/erasure%3D1.0/solver%3DSolverSerialJointSingleHair}{Github Link} 

\paragraph{Offline phase: DEM and hypergraph construction.}
For each choice of code distance $d$, physical error rate $p$, and erasure conversion rate $R_e = 1$, we compile the rotated-memory surface-code circuit using Stim and pass it to the MWPF decoder. From this circuit, MWPF constructs a detector error model (DEM) with detectors $\{D_i\}_{i=1}^m$ and error mechanisms $\{E_j\}_{j=1}^n$, where each $E_j$ is represented as a hyperedge
\[
    F_j \subseteq \{D_1,\dots,D_m\}.
\]
With $R_e = 1.0$, every physical fault is converted into a \texttt{HERALDED\_ERASE} event, so erased qubits are treated as known-location faults with unknown Pauli type. All hyperedges associated with erased qubits must be included in any feasible parity factor.

The hypergraph incidence matrix has the form:
\begin{align}
    H^{(\mathrm{hyp})}_{ij} =
    \begin{cases}
        1 & \text{if detector } D_i \text{ is incident on hyperedge } F_j, \\[4pt]
        0 & \text{otherwise}.
    \end{cases}
\end{align}

With $R_e = 1.0$, every physical error is converted into a \texttt{HERALDED\_ERASE} event, so erased qubits are treated as known-location faults with unknown Pauli type. All hyperedges associated with erased qubits must appear in any feasible parity factor.

All error mechanisms share the same probability $p_j = p$, giving log-likelihood weights:
\begin{align}
    w_j = \log\!\left(\frac{1-p}{p}\right).
\end{align}

All error mechanisms share the same erasure probability $p_j = p$, yielding log-likelihood edge weights
\[
    w_j = \log\!\left(\frac{1-p}{p}\right).
\]
We use the MWPF implementation with \texttt{cluster\_node\_limit = 50} and the \texttt{SolverSerialJointSingleHair} solver. Due to the memory footprint of MWPF, each Sinter task is limited to \texttt{max\_shots = 50{,}000} and \texttt{max\_errors = 1{,}000}, distributed over approximately 60 worker processes.

\paragraph{Online phase: erasure-aware MWPF decoding.}
\begin{align}
    s \in \{0,1\}^m,
\end{align}
and an erasure mask identifying all erased qubits. Let $x \in \{0,1\}^n$ indicate which error mechanisms occur. The MWPF decoder must satisfy the parity constraint:
\begin{align}
    H^{(\mathrm{hyp})} x = s \pmod{2}.
\end{align}

Given these constraints and the requirement that all erasure-associated hyperedges be included, MWPF solves the minimum-weight parity-factor problem:
\begin{align}
    \hat{x}
    =
    \arg\min_{x \in \{0,1\}^n}
    \left\{
    \sum_{j=1}^n w_j x_j \;:\;
    H^{(\mathrm{hyp})} x = s \ (\mathrm{mod}\ 2),
    \ \text{and erasure hyperedges are enforced}
    \right\}.
\end{align}

The resulting parity factor $\hat{x}$ is mapped to a Pauli correction on the data qubits. We apply this correction, measure the logical observable, and classify the shot as a success or logical failure. As in other experiments, the logical error rate is:
\begin{align}
    P_L = \frac{k}{n},
\end{align}
where $k$ is the number of logical failures and $n$ is the total number of shots for that $(d,p,R_e)$ configuration.


\subsection{Experiment 4: Erasure-aware Min-weight Perfect Matching} \label{sec:experiment4}
\begin{itemize}
    \item \href{https://github.com/leigh-johnson/C191A-qubit-minesweeper/tree/main/datasets/circuit%3Dsurface_code%3Arotated_memory_x/decoder%3Dmwpf/erasure%3D1.0/solver%3DSolverSerialJointSingleHair}{Github Link}
    \item Additional Results: \autoref{fig:pymatching-pthresh-erase}.
\end{itemize}

\textbf{Overview.}
This experiment modifies the MWPM baseline in Experiment \nameref{sec:experiment1} to use a fully erasure-converted noise model with $R_e = 1.0$, following the two-step strategy of \citeauthor{gu_fault-tolerant_2025} \cite{gu_fault-tolerant_2025}. In the first step, a Stim circuit with \texttt{HERALDED\_ERASE} channels produces both a syndrome bitstring and an erasure bitstring. In the second step, we build a detector error model (DEM) and decode syndromes with PyMatching, using per-shot edge re-weighting conditioned on the erasure bits.

\textbf{Data.}
We generated datasets for $d \in \{3,5,7,9,11, 13\}$, $p \in [0.003, 0.06]$, and $R_e = 1.0$ using Sinter with \texttt{max\_shots = 500{,}000} and \texttt{max\_errors = 10{,}000} per task, across $\approx 60$ workers. The resulting CSV files are stored alongside the other experiment datasets in our project repository.\footnote{\url{https://github.com/leigh-johnson/C191A-qubit-minesweeper}}

\paragraph{Offline phase: circuit conversion and DEM analysis.}
Starting from the same rotated-memory surface-code circuit used in \nameref{sec:experiment2}, we convert all Pauli faults into heralded erasures. Each physical fault is implemented as a \texttt{HERALDED\_ERASE} instruction followed by one or more dedicated \texttt{DETECTOR} instructions that act as erasure checks. All remaining \texttt{DETECTOR} instructions are treated as standard stabilizer syndrome detectors.

From the converted circuit we derive a DEM via Stim, then analyze it to obtain:

\begin{itemize}
    \item a set of syndrome detector indices $\mathcal{S}$ (standard stabilizers);
    \item a set of herald detector indices $\mathcal{H}$ (one representative detector per erasure event);
    \item for each DEM error $E_j$, its probability $q_j$ and the set of detectors it touches;
    \item a mapping from each error $E_j$ to the herald(s) $h \in \mathcal{H}$ whose detectors it touches.
\end{itemize}

Base log-likelihood weights for each DEM error are given by
\begin{align}
    w^{(0)}_j & = \log\!\left(\frac{1 - q_j}{q_j}\right),
\end{align}
where $q_j$ is the error probability specified by the DEM. When herald $h$ fires, we model errors associated with $h$ as having a larger conditional probability $p_{\mathrm{herald}} = \alpha$ (we use $\alpha = 0.5$), with
\begin{align}
    w^{(\mathrm{herald})} & = \log\!\left(\frac{1 - \alpha}{\alpha}\right),
\end{align}
and define the per-herald weight shift
\begin{align}
    \Delta w_{h,j} & =
    \begin{cases}
        w^{(\mathrm{herald})} - w^{(0)}_j & \text{if error $E_j$ touches herald } h, \\[4pt]
        0                                 & \text{otherwise}.
    \end{cases}
\end{align}

We then construct a single PyMatching graph from the DEM. This graph is reused across all shots; only the edge weights are updated per shot.

\paragraph{Online phase: per-shot edge re-weighting and MWPM decoding.}
Each noisy shot yields a bitstring of all detector outcomes,
\begin{align}
    z & \in \{0,1\}^{m},
\end{align}
from which we extract:
\begin{align}
    s & = z|_{\mathcal{S}} \quad\text{(syndrome detectors)}, \\
    h & = z|_{\mathcal{H}} \quad\text{(herald detectors)}.
\end{align}
Interpreting $h$ as a binary row vector, we compute the per-shot edge weights as
\begin{align}
    w^{(\mathrm{shot})}_j & = w^{(0)}_j + \sum_{h' \in \mathcal{H}} h_{h'} \, \Delta w_{h',j},
\end{align}
or in vector form,
\begin{align}
    \mathbf{w}^{(\mathrm{shot})} & = \mathbf{w}^{(0)} + h \, \Delta W,
\end{align}
where $\Delta W$ is the matrix whose entries are $\Delta w_{h,j}$. These weights are passed to PyMatching, which performs minimum-weight perfect matching on the DEM graph and returns a predicted set of logical observable flips for that shot.

As in previous experiments, we map the decoder output to a Pauli correction on the data qubits, apply the correction, and compare the resulting logical measurement to the ideal value. The logical error rate for a given $(d,p,R_e)$ configuration is then
\begin{align}
    P_L = \frac{k}{n},
\end{align}
where $k$ is the number of logical failures and $n$ is the total number of shots.

\section{Discussion}\label{sec:discussion}
\paragraphsc{Reduced tolerance of errors in our surface code simulations}
\autoref{tab:1}.
In the case where depolarizing noise is modeled with purely Pauli errors, we reference the physical error threshold $p_{thr}$ published by \citeauthor{wu_erasure_2022} ($p_{thr} = 0.937(4)\%$) and \citeauthor{acharya_quantum_2025} ($p_{thr} \approx 1\%$) \cite{wu_erasure_2022}\cite{acharya_quantum_2025}.

In Experiment1, we visually estimated a much \textit{lower} error ($p_{thr} = 0.775$, \%err $=22.5\%$) for our X-rotated surface code with pure Pauli noise and the PyMatching decoder. We ruled out decoder implementation as a contributing factor (under this particular noise regime) after determining a similar result in our ablation study of MWPF in Experiment2 ($p_{thr} = 0.750$, \%err $=25.0\%$). We attribute this systemic error to multiple sources, in order of signifiance:

\begin{itemize}
    \item \autoref{fig:stim-circuit-gen}. We intended to assume perfect stabilizer measurements, but our circuit implementation applied the depolarizing error channel to each data qubit per measurement round.
    \item We applied the depolarizing noise channel to one and two-qubit gates at the same rate. Our references consider only two-qubit gates.
\end{itemize}

Depending on the experiment procedure demands, it may be useful to extend or customize Stim's circuit generator in our own codebase.

\paragraphsc{High Uncertainty in MWPF Experiments}
In our MWPF experiments, our Monte Carlo simulation was limited to 10,000 - 50,000 shots at a time (vs. 500,000 per single run in other trials). We aggregate the datasets from many (5+) in order to compare against other experiments. Fewer samples resulted in a wider confidence interval for MWPF samples, especially at low physical error rates (see \autoref{fig:mwpf-pthresh} and \autoref{fig:mwpf-pthresh-erase}). We attempted to gather enough data to make a fair comparison between our visual estimations for $p_{thr}$, especially for the sampling region around the threshold. However, the binomial fit method in our $P_L$ vs. $p$ plots is very sensitive to outlying datapoints. A visual estimate at the extrema of the very wide confidence interval for $d=7,9,11$ in \autoref{fig:mwpf-pthresh-erase} puts the $p_{thr}$ region anywhere from $\approx 3-6$\%. We report the most convervative value in our results table.

\section{Appendix: A Fun Sidequest: Profiling a Memory Leak}\label{sec:memleak-sidequest}
During our initial experiments with MWPF, we noted a memory leak during erasure-aware trials (see \autoref{fig:mwpf-memleak}). Using a combination of flamegraphs to analyze hot CPU/blocking GIL paths and a memory profiler to rank allocation requests by size/frequency, we realized \href{https://github.com/yuewuo/mwpf/blob/b8444428f999457208c4b0956f3f1c745a0ec2d5/src/python/mwpf/ref\_circuit.py}{ref\_circuit.py} and \href{https://github.com/yuewuo/mwpf/blob/b8444428f999457208c4b0956f3f1c745a0ec2d5/src/python/mwpf/heralded\_dem.py}{heralde\_dem.py} (quite reasonably) uses Python's functools.cached\_property decorator to cache computationally-expensive walks of the hypergraph model. The memory allocations are associated with a Python object instance and are freed automatically by a garbage collector when the Python object is destroyed. We noted RefCircuit instances holding memory allocations (via parent HeraldedDetectorErrorModel) even after the related sinter. Task had finished (but other tasks were still running). This is only a guess, as we were not able to patch and validate this particular hypotheses. Instead, we opted to side-step the issue by replacing some functools.cached\_property usage with functools.lru\_cache, which implements a last-recently used cache on per class definition (instead of per object-instance). As a result, we needed many more CPU cycles to complete our simulation but the memory footprint was contained to fit our availablae hardware (64 cores, 126GB DDR4 RAM, 112GB NVME-backed disk swap space).

\section{Appendix: Additional Notes on Leakage}\label{appendix:leakage}
A leakage occurs when a qubit ``leaks'' out of the computational subspace (described by a two-dimensional Hilbert space) into a state that can only be described with a higher-order Hilbert space. If leakage goes undetected, the error compounds over time as it spreads through a multi-qubit interactions. Leakage can be stochastically modeled with a 3-level system (qutrit) with orthonormal basis: $\set{\ket{0}, \ket{1}, \ket{2}}$. Leakage events are assumed to be discrete and occur independently with probability $p_{\text{leak}}$ at each gate operation acting on the qutrit \cite{suchara_leakage_2014}. The leakage error $E_{E_{\uparrow}}$ on the $j$th qutrit in the system can then be understood as:
\begin{align}E_{\text{leakage}}(\rho_j) & = (1-p_{\text{leak}})\rho_j + p_{\text{leak}}\ket{2}\bra{2} & \quad \text{[Leakage error channel \cite{suchara_leakage_2014}]}
\end{align}

Leakage-reduction units (LRUs) were proposed as a way to convert leakage errors into Pauli-type errors, based on a one-bit teleportation protocol that effectively moves the logical state from the physical qubit in the leaked state to a freshly-prepared physical qubit \cite{suchara_leakage_2014}.

All species of qubit experience leakage errors, but it's important to note the underlying \emph{physical} processes look and behave very differently despite sharing a common mathematical description.


Transmon leakage. Transmon single and two qubit gates rely on coherent microwave driving to transition between computational basis states. Two qubit gates such as the controll Z and controll X gates are the primary source of leakage in transmon qubits because of their temporary usage of states outside of the computational basis to induce phase and bit flips in the target qubit. For example, when applying a control Z gate on transmon hardware to the state {$\ket{11}$}, temporarily force both excitons onto one qubit, pushing it into the second excited state, {$\ket{2}$}, and letting the other qubit fall into the ground state, {$\ket{0}$}, before allowing the system to relax back into {$\ket{11}$} with the intended phase shift applied. However, there is a nonzero chance that the system does not relax properly, and leaves one of our qubits in the {$\ket{2}$} state, causing a leakage error in our system.

Neutral atom / Rydberg leakage. Neutral atom quantum computers exploit the large effective atomic radius of Rydberg states to perform two qubit gates. When an electron is excited to a Rydberg state, the separation between the electron and the now ionized nucleus creates an electric dipole field, which shifts excitation energy of the Rydberg state, an effect called Rydberg blockade. Following the protocol from Jaksch et. al, to perform a control Z gate, apply a {$\pi$} pulse to excite the control qubit into a Rydberg state, apply a 2{$\pi$} pulse to the target qubit, and then apply a {$\pi$} pulse to deexcite the control qubit \cite{Jaksch_Fast_Quantum_gates_2000}. If both qubits are in the {$\ket{0}$} then the state will remain unchanged, but if exactly one qubit is in the {$\ket{1}$} state then a rotation by 2{$\pi$} and thus a phase shift of -1, will be applied. If both qubits are in the {$\ket{11}$} state then after the first pulse, the Rydberg blockade will prevent the second excitation and a phase of -1 will be applied. Finally apply a Pauli Z gate to both qubits to shift the states -{$\ket{01}$ and -{$\ket{10}$ to {$\ket{01}$ and {$\ket{10}$. Occasionally when applying this protocol, the Rydberg state will not decay back to the {$\ket{1}$} state, and will instead decay to an orbital state outside of our computational basis, causing a leakage error. \cite{morgado_quantum_2021}

Leakage-detection units (LDUs) were developed to address leakage errors in superconducting qubits, by periodically coupling a data qubit to an acilla that flags when the data qubit leaves the computational subspace. The flagged data qubit can be reset/replaced during subsequent error-correction cycles, effectively treating the flagged qubit as an erasure error.

Neutral atoms / Rydberg arrays, each atom is arranged into a known position using optical tweezers. Although the lattice/trap is situated inside a vacuum chamber, some nonzero amount of background gas collisions or thermal energy transfer from the environment can eject an atom from its lattice site

\subsection{Appendix: Erasure Tolerance and Enhancements}

If left uncorrected, erasure errors pose a existential threat to encoded logical qubits that utilize the surface code encoding schema. While it is possible to compensate to some degree for erasure errors via the introduction of superstabilizers, the accumulation of erasures will eventually render your state unreconstructable if left unchecked. Kobayashi et al showed that a probability of erasure as low as 0.1\% can lead to logical failure rates increasing with code distance in regimes where the Pauli error rate is less than or on the order of 0.1\%. This suggests that to build a functional quantum computer, using the standard surface code encoding and the minimum weight perfect matching algorithm, one would need $p_{erase} << p_{pauli}$.
\cite{kobayashi_erasure-tolerance_2025}

\begin{align}
    E_d & \propto \dfrac{p}{p_{thr}}^{(d+1)/2} & \quad \text{[Logical error rate]}
\end{align}

Therefore when $p << p_{thr}$, the logical error rate is supressed exponentially with code distance. The exponential supression factor $\Lambda$ is approximately the linear relation between $p_{thr}$ and $p$: \cite{acharya_quantum_2025}.

\begin{align}
    \Lambda & = \dfrac{E_d}{E_{d+1}} \approx  \dfrac{p_{thr}}{p} & \quad \text{[Supression factor]}
\end{align}
